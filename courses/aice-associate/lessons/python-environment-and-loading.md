# Python 환경과 데이터 로딩

Associate는 Python 실기와 제한적 오픈북 환경이다. 노트북의 라이브러리 버전과 난수 시드를 먼저 기록하고, CSV는 `pd.read_csv`, 엑셀은 `pd.read_excel`로 읽은 뒤 `head`, `shape`, `dtypes`를 확인한다. 경로·인코딩·구분자를 명시해 같은 입력을 재현한다.

## 목표·시험 포인트
입력 타입과 결측 표기를 통제하고 로딩 직후 구조를 확인한다. 시험에서는 경로·인코딩·날짜 파싱을 명시했는지 판단한다.

## 먼저 이해할 이론

데이터 로딩은 분석의 첫 번째 모델링 가정이다. 한 행이 고객인지 주문인지, 한 열의 단위와 시간 기준이 무엇인지 모르면 뒤의 통계와 모델 점수도 해석할 수 없다. `shape`는 규모, `dtypes`는 해석 방식, `head`는 실제 값의 모양을 보여주므로 셋을 함께 확인한다. 날짜를 문자열로 남기면 정렬과 기간 계산이 문자열 규칙을 따를 수 있다.
```python
import pandas as pd
df = pd.read_csv("customers.csv", na_values=["", "NA", "-"])
df["joined_at"] = pd.to_datetime(df["joined_at"], errors="coerce")
print(df.shape, df.dtypes, df.head(3))
```
흔한 실수는 실행 위치에 의존하는 상대 경로와 문자열 날짜다. synthetic CSV를 만들고 스키마 요약표를 저장한다.

쉬운 예로 `2025-10-2`와 `2025-10-10`을 문자열로 정렬하면 기대와 다른 순서가 될 수 있다. `to_datetime(..., errors="coerce")` 뒤에는 변환 실패 개수를 확인해야 한다. 모든 실패를 조용히 버리는 것은 정제가 아니라 정보 손실이다.

스스로 설명하기: “왜 로딩 직후 결측 표기와 날짜 타입을 확인해야 하는가?”에 행의 의미, 타입, 실패 개수라는 세 근거가 들어가는지 확인한다.
