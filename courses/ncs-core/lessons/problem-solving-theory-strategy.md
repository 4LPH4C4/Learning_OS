# 원인 분석·대안 평가·실행 검증 전략

## 문제와 원인을 분리하기

문제는 `기대 상태와 현재 상태의 차이`다. “고객이 불만이다”보다 “7월 응답 시간이 목표 4시간에서 11시간으로 늘었다”가 해결 가능한 문제 정의다. 원인 후보는 아직 사실이 아니므로 데이터로 검증해야 한다.

## 표준 절차

1. 현재·목표·범위·영향을 수치화한다.
2. 사람 탓을 하기 전에 프로세스·도구·환경·정보의 원인 후보를 넓힌다.
3. 원인별로 확인할 데이터와 반증 조건을 정한다.
4. 비용·효과·실행 가능성·위험을 같은 기준으로 비교한다.
5. 작은 범위에서 실행하고 지표로 효과를 확인한다.

## 자주 쓰는 도구

- 5 Why: 인과를 계속 묻되 증거 없는 이야기를 만들지 않는다.
- 원인-결과도: 사람·방법·도구·환경 등 후보를 구조화한다.
- 파레토: 빈도나 영향이 큰 원인을 먼저 찾는다.
- 의사결정행렬: 기준과 가중치를 먼저 정한 뒤 대안을 평가한다.
- PDCA: 실행 결과를 확인하고 표준화하거나 다시 조정한다.

## 선택지 함정

- 증상만 줄이고 원인을 확인하지 않는다.
- 전체 적용부터 해 되돌릴 수 없다.
- 좋아 보이는 대안을 정한 뒤 평가 기준을 바꾼다.
- 상관관계를 원인으로 단정한다.
- 이해관계자의 제약이나 안전 위험을 누락한다.

## 실무 훈련

반복되는 업무 지연 한 건을 골라 문제 정의, 원인 후보 3개, 각 후보의 확인 데이터, 1주 안에 가능한 작은 실험을 작성한다.
